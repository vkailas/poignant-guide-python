    Is it better to Check a type or just Try a method?

    Many Pythonistas prefer to charge ahead blindly! We assume the object can do it, try it out, and use a try/except block to cleanly catch the mess if things go wrong. python

    >>> try:
...     print(sparky.cast_spell())
... except AttributeError:
...     print("This pet is completely mundane.")
...

    This is known as Easier to Ask for Forgiveness than Permission (EAFP).

    Why do Pythonists prefer EAFP?

    1. Speed: Checking first and then fetching the attribute means Python has to look up the name twice. EAFP only looks it up once.
    2. Readability: It separates the "happy path" (what you expect to happen) from the error-handling fallback code cleanly.

    Indexing and Lookups with Brackets

    As we have seen before, the square brackets attached to an object (e.g. names[3], cat_toy["name"], name[1:]) can be used to lookup parts inside any List, Dictionary or String objects, as these objects provide a __getitem__ dunder method.

    For strings, lists, and dictionaries, we can use square brackets attached to an object like so:

    word[0] # string
shopping_list[2] # list
phone_book["Alice"] # dictionary

    We can also slice to get multiple elements using the colon for lists and strings. 

    shopping_list[0:2] # list

    The value inside the brackets is like a label we've slipped to our fork lifts operator between the two fork lift's prongs ["Alice"]. He reads the label and find the corresponding item to fetch for us.

    • For strings and lists, the label is usually an integer position, such as 0 or 5. We can also use slices, such as 1:4, to ask for a whole range of items at once.
    • For dictionaries, the label is called a key. Rather than looking up an item by position, a dictionary looks it up by name. Keys are often strings, but they can also be numbers, tuples, and other immutable objects.

    For mutable containers like lists and dictionaries, Python lets us use square brackets in assignment, to swap out or add items. Behind the scenes, this relies on a hidden mechanism called the __setitem__ method. When you write obj[idx] = value or obj[key] = value, Python is secretly calling that method for you.

    For example: names_list[3] = "Joanna", we see square brackets to sit on the left of the equal sign.

    Here's a table that summaries what we have learned so far:

    Type Get Set
    String my_string[index] Not allowed (strings are immutable)
    List my_list[index] my_list[index] = value
    Dictionary my_dict[key] my_dict[key] = value

    Let's try some lookup and assignment examples using what we've learned.

    Decoding the Scroll

    Now, this is a scroll of enlightenment after all, so read its ancient knowledge at your own risk. But if we want to graduate and learn Python, we read its secret contents could help.

    We can decode the scroll gracefully using the join() method that comes free with all Python strings. The basic usage of join() is "separator".join(list_of_strings). So, here we call join() like so: separator_string.join(list_of_strings). 

    from scrolls import scroll
bytes_strings = ["".join(str(b) for b in scroll[i:i+8]) for i in range(0, len(scroll), 8)]
decoded = "".join(chr(int(b, 2)) for b in bytes_strings)
print(decoded)

    The @property decorator acts as a gatekeeper. The outside world can look at a ticket's picks through the picks property, but it cannot assign a new value unless we explicitly provide a setter.

        if len(set(picks_list)) != self.NUM_DRAWS:
